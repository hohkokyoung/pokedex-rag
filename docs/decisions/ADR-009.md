# ADR-009: Rules every client must agree on live on the backend

**Status:** Accepted

## Context

Team grades, the team profile, the type chart and the Alcremie spin rules were computed
or hard-coded in `frontend/lib/`. A second client (a planned mobile app) would have to
copy them in another language. The backend couldn't see them either: the grade a user
saw couldn't be calculated by the summary, the eval or any server-side report.

## Decision

If two clients disagreeing about something would be a bug, the backend computes it
and clients display it. That covers:
- the team rating and profile (`services/team_rating.py`, `services/team_profile.py`),
  returned with the opponent-free team analysis;
- the type chart (`GET /api/types/chart`, from the ingested data);
- the Alcremie spin guide (`services/alcremie.py`, on the detail response);
- the evolution labels, chips and description per stage (`services/evolution_display.py`,
  as `display` on each evolution stage). Added 2026-10-09, when the mobile app needed
  them; earlier this ADR left them client-side.

Clients keep presentation (colours, grade tone, wording of vs-opponent factors) and
maths that must react instantly to input: the damage calc (ADR-006) and the catch
rate.

The rating and profile were ported literally and are pinned to the old TypeScript's
output by frozen golden cases (`backend/tests/fixtures/team_rating_*.json`). They keep
JavaScript's half-up rounding.

## Consequences

- A new client reads grades and the chart from the API instead of re-implementing them.
- Changing a grade rule is a backend change plus a test, with no frontend port.
- The type chart can't drift from the data the assistant answers from.
- Amends [ADR-007](ADR-007.md): grades stay deterministic but are computed in Python.
- Details: [team-coach.md](../architecture/team-coach.md#deterministic-engines-no-llm).
