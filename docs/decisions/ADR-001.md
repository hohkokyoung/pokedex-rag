# ADR-001: PokéAPI data is ingested offline, never called at runtime

**Status:** Accepted

## Context

The assistant must answer only from data it can cite, and the app is single-user and
local-only. A live API would add latency, rate limits, network failure modes and
answers that change under the same question.

## Decision

The PokéAPI CSV dataset is downloaded and ingested into Postgres by host-side
`make` targets. At runtime the backend reads only the DB; sprites are served from
`data/sprites/`.

## Consequences

- Answers and evals are reproducible against a fixed dataset.
- Data gaps (e.g. encounters end at Sword/Shield) are the dataset's, and the agent
  must abstain rather than look elsewhere.
- Data changes go through the pipeline — see
  [data-pipeline.md](../guides/data-pipeline.md).
