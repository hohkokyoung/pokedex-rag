# web-to-flutter profile: pokérag

## Repo
- **Web:** Next.js 16 / React 19 / Tailwind v4 in `frontend/`.
  - Styles: `frontend/app/globals.css` (search the component's class prefix, e.g.
    `.lc-tg`, `.ax-`, `.mu__`).
  - Design: `DESIGN.md` and `PRODUCT.md`.
  - Data: `frontend/lib/api.ts`.
  - Dev: `make up` serves http://localhost:3000.
  - What each page does: `docs/product/<page>.md`.
- **App:** Flutter 3.44.1 via fvm in `mobile/`, iOS and Android, bundle id
  `dev.pokerag.pokerag`.
- **Backend:** FastAPI in `backend/` on :8001.
  - The app's client is generated from an OpenAPI slice: list the path in
    `tools/mobile/openapi_snapshot.py`, then run `make mobile-api`.
  - `backend/tests/test_mobile_openapi.py` fails when the snapshot is stale.

## Stack
- **State:** flutter_riverpod 3.
- **Router:** go_router. Routes live in `mobile/lib/app.dart`, always through `_go(...)`
  (a `MaterialPage`); tabs are `StatefulShellRoute` branches.
- **HTTP:** dio and retrofit, generated by swagger_parser (`mobile/lib/api/`).
- **Images:** `Artwork` / `thumbUrl`.
- **Theme:** `mobile/lib/theme/theme.dart`. It holds `AppText`, the phone type scale
  (body 14, small 12.5, label 12, headline 16.5); use it, never `TypeScale`.
- **Tokens:** `mobile/lib/theme/tokens.g.dart` (`Palette`, `Radii`, `Space`,
  `TypeColors`). It's generated from DESIGN.md by `make mobile-tokens`; never hand-edit.

## Commands
- **Run the app:** `make mobile-ios`.
- **Simulator build:** `cd mobile && fvm flutter build ios --simulator --debug`, then
  `xcrun simctl install/launch` with bundle id `dev.pokerag.pokerag`.
- **Tests:** `make mobile-test` for the app, `make test` for the backend.
- **Lint:** `make lint`, and `fvm flutter analyze` in `mobile/`.

## Tests
- **Harness:** `pumpApp(tester, backend, {location, size})` in
  `mobile/test/support/app_harness.dart`. It builds the real app via `appFor(router)`.
- **Fake backend:** `FakeBackend`, `fixture()` and `listPage()` in
  `test/support/fake_backend.dart`; fixtures in `mobile/test/fixtures/` (recorded with
  `curl` from :8001).
- **Gotchas:**
  - JSON is decoded synchronously in tests via `dioTransformerProvider`;
  - call `flush(tester)` at the end of a test that triggers a refetch;
  - `openPart(tester, part)` opens a Pokémon page segment.

## House rules
- **Look:** the website's light Instrument language, cleaner. Not a new identity.
  Three standalone themes were rejected on 2026-10-10.
- **Platform feel:** iOS on both platforms:
  - no ripples (`Pressable`);
  - Cupertino slides with swipe-back, each page on its own ground;
  - Cupertino spinner, alerts and switches;
  - check-row sheets, never dropdown menus.
- **Business rules:** server-side; both clients read them (ADR-009). A web-only rule
  moves to the backend with a test, and is never mirrored in Dart.
- **Corners:** 6 chips, 8 insets, 10 controls (pills, buttons, inputs, send), 14
  panels. No stadiums or circles.
- **Red** only on actions and the current selection; Ask is the red tab.
- **Type:** the phone scale. Type chips need room (8–10pt sides), with counts inside
  the chip.
- **Type pickers** look like the website's `.lc-tg`: grey names; picked means the
  type's colour with a glow. Faded solid chips were rejected.
- **Type filter:** the Pokédex takes any number of types; any may match (server rule).
- **Answers** (Ask and both coaches) share `AnswerText`:
  - the verdict first;
  - artwork rows;
  - small red citation chips.

  Suggestions are `SuggestionRows`, after the question box; "Ask next" comes after the
  answer.
- **Show less:** top six plus "Show all"; problem rows first, plus "Show the other N";
  formulas, IVs and field settings fold away.
- **Many options** (forms, moves) go in a searchable sheet behind one pill, never a
  wall of chips.
- **Matchups** are grouped as on the website (Takes more from, Resists, Immune to,
  Hits), each with a coloured multiplier.
- **Lookup** opens on the full finder; there's no empty search page.

## Rejected
- Fade or shadow where a list scrolls under a fixed header. Cut off cleanly instead
  (2026-10-10).
- A big red "Ask" block in the question box, and the round send button (2026-10-10).
- Spaced-out chips for suggestions, and the boxy tray with a separate Ask button
  (2026-10-10).

## Process
- **Specs:** OpenSpec (`openspec/`): propose → apply → archive, one change per
  shippable piece; `mobile/<capability>` specs.
- **Docs to update:**
  - `docs/product/mobile.md`;
  - `docs/components/mobile.yaml` for new endpoints;
  - the web page's doc in `docs/product/` when a shared rule changes.
- **Commit** on `main` with Co-Authored-By. Push only when asked.
- **Never** call PokéAPI at runtime. Ask before spending LLM quota (Ask questions that
  aren't closed-form spend Groq tokens).
